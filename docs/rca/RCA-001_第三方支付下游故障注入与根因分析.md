# RCA-001：第三方支付下游故障注入与错误转换验证

## 基本信息

| 字段 | 内容 |
|---|---|
| 类型 | 下游依赖故障注入 / RCA 练习 |
| 接口 | `POST /orders/pay` |
| 环境 | Windows，本地 FastAPI，pytest TestClient |
| 日期 | 2026-08-24 |
| 状态 | 已完成故障注入验证 |
| 真实外部调用 | 无，使用 `pytest-mock` 替换 |

## 背景

支付接口调用 `call_third_party_payment()` 模拟第三方支付服务。测试通过 Mock 注入两类下游故障，验证当前服务是否能将依赖异常转换为明确的 HTTP 状态码，而不是直接返回未处理的 500。

## 复现命令

```powershell
python -m pytest test_api.py `
  -k "pay_order_timeout_fault_injection or pay_order_service_error_fault_injection" `
  -q `
  --log-cli-level=INFO
```

## 故障一：下游超时

### 注入方式

将 `main.call_third_party_payment` Mock 为：

```python
requests.exceptions.Timeout("Mocked Third-party Connection Timeout")
```

### 时间线

```text
客户端发送 POST /orders/pay
→ FastAPI 接收请求
→ 调用第三方支付函数
→ 注入 Timeout
→ pay_order 捕获 requests.exceptions.Timeout
→ 转换为 HTTP 504
→ 客户端收到 504
```

### 日志证据

```text
request_id=de6d254c1b234231a51728a76ceea30d
method=POST
path=/orders/pay
status=504
duration_ms=7.48
```

```text
HTTP Request: POST http://testserver/orders/pay
HTTP/1.1 504 Gateway Timeout
```

### 结论

该结果符合预期。504 表示当前服务作为调用方等待下游时未获得及时响应，直接原因是下游 Timeout。

## 故障二：下游普通异常

### 注入方式

将 `main.call_third_party_payment` Mock 为：

```python
RuntimeError("payment service unavailable")
```

### 时间线

```text
客户端发送 POST /orders/pay
→ FastAPI 接收请求
→ 调用第三方支付函数
→ 注入 RuntimeError
→ pay_order 捕获普通 Exception
→ 转换为 HTTP 502
→ 客户端收到 502
```

### 日志证据

```text
request_id=1619a41e99fa43efa5f22a90dcb90b8d
method=POST
path=/orders/pay
status=502
duration_ms=2.71
```

```text
HTTP Request: POST http://testserver/orders/pay
HTTP/1.1 502 Bad Gateway
```

### 结论

该结果符合预期。502 表示当前服务调用下游时发生普通依赖错误，不能把它直接归因于当前服务内部崩溃。

## 根因与表现的区分

```text
根因：下游调用抛出 Timeout 或 RuntimeError
服务处理：捕获异常并转换为明确状态码
外部表现：504 或 502
```

状态码不是根因本身。真实生产 RCA 还需要结合下游服务日志、网络连接、超时配置和依赖可用性指标。

## 回归结果

```text
2 passed, 36 deselected in 0.12s
```

已验证：

- Timeout 映射为 504；
- 普通下游异常映射为 502；
- 没有将这两类已知故障错误地暴露为 500；
- 每次请求都有独立 request id；
- 应用日志包含请求路径、状态码和耗时。

## 证据边界

本次使用 TestClient 和 Mock：

```text
pytest → TestClient → FastAPI → Mock 下游函数
```

日志中的 `http://testserver` 是 TestClient 的内部测试地址，不代表真实外部网络调用。`duration_ms` 也不代表真实第三方超时等待时间。

因此本次不能证明：

- 真实支付服务一定会返回同样异常；
- 真实网络超时的耗时和重试行为；
- 生产环境的下游可用性；
- 当前系统已经具备重试、熔断或降级能力。

## 面试表述

> 我使用 pytest-mock 对第三方支付调用进行故障注入，分别模拟 Timeout 和普通依赖异常。服务将 Timeout 转换为 504，将普通下游异常转换为 502，并通过 request id 和 duration_ms 记录请求证据。测试结果为 2 passed。由于测试使用 TestClient 和 Mock，结论只覆盖当前服务的异常处理逻辑，不代表真实第三方网络性能或生产可用性。
