# BUG-001：新增商品允许负价格并返回 201

## 基本信息

| 字段 | 内容 |
|---|---|
| 缺陷类型 | 功能缺陷 / 参数校验缺失 |
| 所属模块 | 商品管理 / 新增商品接口 |
| 接口 | `POST /items` |
| 状态 | New / Open |
| 严重程度 | Major / S2 |
| 优先级 | High / P1 |
| 发现日期 | 2026-08-22 |
| 测试环境 | Windows，本地 FastAPI，SQLite `dev.db` |

## 缺陷标题

`[商品管理][新增商品] price 为负数时接口仍返回 201 并接受该商品`

## 前置条件

1. FastAPI 服务已启动。
2. `base_url` 指向 `http://127.0.0.1:8000`。
3. 商品 ID `990001` 尚不存在。

## 复现步骤

1. 向 `POST /items` 发送新增商品请求。
2. 请求体中的 `price` 设置为 `-1`：

```json
{
  "id": 990001,
  "name": "Negative Price Test Item",
  "price": -1,
  "category": "test"
}
```

3. 发送请求并观察状态码和响应体。

## 预期结果

1. 接口拒绝 `price <= 0` 的商品数据。
2. 接口返回约定的 4xx 状态码；若使用 Pydantic 字段约束，建议返回 `422 Unprocessable Entity`。
3. 响应中明确指出 `price` 必须大于 0。
4. 非法商品不得写入数据库。

## 实际结果

1. 接口返回 `201 Created`。
2. 响应提示商品创建成功。
3. 响应数据中包含 `"price": -1.0`。

## 影响分析

负价格商品可能进入商品展示、订单金额计算和统计流程，造成业务数据异常。新增接口接受负价格，而修改接口拒绝非正数价格，两个接口的校验规则不一致。

## 证据

1. Postman 创建请求返回 `201 Created`，响应体包含商品 ID `990001` 和 `price: -1.0`。
2. 清理请求 `DELETE /items/990001` 返回 `204 No Content`。
3. 清理后查询 `GET /items/990001` 返回 `404 Not Found`，仅用于证明测试数据已清理。

> 本次未在删除前保存 GET 查询截图，因此不将删除后的 404 作为“创建后持久化成功”的证据。核心缺陷证据是非法请求被接口以 201 接受。

## 初步定位

- `ItemCreate.price` 当前仅声明为 `float`，没有大于 0 的字段约束。
- 新增接口只检查商品 ID 是否重复，没有检查价格。
- 修改接口已经对 `price <= 0` 返回 400，新增和修改规则不一致。

## 修复建议

1. 在共享请求模型中统一增加 `price > 0` 约束。
2. 为新增接口补充 `price=0` 和 `price<0` 的自动化测试。
3. 断言接口返回 4xx，并通过数据库查询确认非法记录没有落库。

## 清理结果

测试商品 `990001` 已通过删除接口清理，删除请求返回 `204 No Content`。
